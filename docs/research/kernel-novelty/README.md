# What the Hecke kernel contributes

The original work in this repository is the analysis of a particular Lean development and the software that makes part of it executable. Its strongest finding is that a reader can trace two specific definitions through Alpöge’s argument, see the different jobs they do, and reproduce their arithmetic from small tables. The evidence supports credit for that investigation and its software. The formulas, their use together, and the headline level-11 result all have direct precedents. ## Earlier authors already paired the two sums

Martin and Wakatsuki give an especially close comparison. In §2, equation (2.2) computes mass by summing reciprocal stabilizer orders over a finite class set. Equation (2.5) gives a Hecke action on functions on that same set by summing over representatives of a double coset. The distinction matters here. One sum ranges over global classes, the other over local neighbors. In the repository, what they share is ordinary exact addition once someone has supplied the entries. The mass calculation takes reciprocals before adding. The Hecke calculation applies a normalization afterward. [Martin and Wakatsuki, §2](https://arxiv.org/pdf/1907.03417#page=6) · [Standalone Lean definitions](../../../lean/HeckeMassKernel/Finite.lean)

Gross printed the README’s exact level-11 matrix in 1987, with rows `(1, 2)` and `(3, 0)`. Its eigenvalues are 3 and −2. Sage even displays the reciprocal weights 1/4 and 1/6 and the transposed matrix as coefficients of one Brandt series. Those agreements make the example a good independent check on stabilizer and matrix conventions. [Gross, §6](https://wstein.org/papers/bib/Gross-Heights_and_the_Special_Values_of_L-series.pdf) · [Sage Brandt series](https://doc.sagemath.org/html/en/reference/modfrm/sage/modular/quatalg/brandt.html#sage.modular.quatalg.brandt.BrandtModule_class.brandt_series)

## The proof trace answers a different question

Alpöge already states both reductions explicitly. `classMass_eq_sum_of_bijective` supplies the finite sum given a complete, bijectively indexed set of representatives. `hecke_apply` supplies the normalized pointwise formula. What the repository adds is an account of **where those statements matter in this particular development**. One branch uses mass to identify a volume. Another specifies how applying the Hecke operator to a target form must agree with a prescribed value, and carries that compatibility across a change of setup. A reader can follow each path from the named root declaration. That is evidence of a dependency in the pinned source. Evaluating the level-11 example is a separate exercise. ## The executable interface makes the boundary testable

The design choice is where to start computing. Given stabilizer orders or sampled rational values, a small Lean program can supply expected answers for independent C and Rust implementations. For example, the replay checks 270 matrix entries by counting recorded neighbor destinations. The conclusions depend on the supplied destinations being correct. The standalone proofs cover the rational definitions and examples. A formal equivalence to the upstream operators and all-input correctness of the native libraries remain open. [Replayed cases](../../replayed-cases.md) · [Verification scope](../../verification.md) · [Specification](../../specification.md)

The contribution is therefore stated as something a reader can verify. The repository traces how Alpöge’s formalization uses class mass and Hecke action, isolates the exact arithmetic each requires once its finite data are supplied, and publishes a standalone Lean specification with replayable C and Rust examples.
